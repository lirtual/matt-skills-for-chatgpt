# ADR-0001：最小 Skills-only ChatGPT 适配架构

- 状态：已接受（设计决策），**插件实施尚未授权**
- 日期：2026-10-18
- 关联：Q1–Q21，尤其 Q19 优先于 Q18；Q20 明确 Q7–Q12；Q21 接受七项深度审查修订

## 背景

需要将 Matt Pocock 正式发布的 Skills 适配到 ChatGPT，以最终替换 Curated。
上游部分工作流依赖终端、项目文件、独立代理及并行 worktree，单纯安装 Skills 不会自动授予这些能力。

比较过的方案包括原样复制并声称兼容、重新建立 MCP/代理执行服务、以及 Skills-only 复用既有工具并明确能力限制。

## 决策

1. 使用独立个人私有 Skills-only 插件 `matt-skills-for-chatgpt`，展示名 `Matt Skills for ChatGPT`，声明非官方。
2. 固定上游 Commit，只迁移正式发布清单中的 27 个 Skills、配套材料及调用策略，保留许可证和第三方署名。
3. 保留上游工作流与依赖关系，仅进行必要的 ChatGPT 适配；使用原始名称，不新建专用路由、UI、数据库、MCP Server 或 Worker。
4. 根据实际连接情况复用 GitHub、文件、执行及 Remote Control 工具；对无法等价执行的部分诚实标注完整／条件／不支持，不伪造测试、并行或后台执行。
5. 调用策略和外部工具授权分离。只读遵守既有授权，写入受任务范围约束，高风险写入遵守独立确认。
6. 项目配置优先复用，只检测不擅自修改；确需写入由用户授权。
7. 静态和调用策略全面检查，核心链路真实验收；安装后检查插件个人私有归属与可调用性，通过后才卸载 Curated，失败保留旧版。
8. 用独立 Git 仓库管理来源和适配变更，上游手工审查后升级，不自动同步与发布。

## 好处

- 最小架构和运维面，源码与适配差异可追溯。
- 复用现有工具和项目约定，不重复建设通用执行平台。
- 明确各 Skill 的内容完整性与实际能力差异，降低误报成功的风险。

## 代价

- 缺乏独立终端或子代理的会话只能条件支持部分 Skills。
- Curated 额外功能不自动继承。
- 上游升级需要人工比对与回归验证。
- 创建工具可能默认活动工作区，必须验证最终个人作用域。

## 未采用的方案

- 新建专用 MCP/Worker 执行后端：增加部署、凭据与长期维护，没有已确认需求支撑。
- 为每个 Skill 重新实现专属 ChatGPT 版本：偏离上游、升级困难。
- 两套插件长期并存：重复工作流及调用不确定性，不符合最终替换目标。

## 复核条件

仅当核心工作流无法在已授权环境完成或用户明确需要真正的并行代理执行时，重新审视执行架构；此 ADR 不构成新后端、插件创建或旧版卸载的授权。
